## Key discoveries

### The driver set is much bigger than planned

The plan listed 3 drivers (SurfaceSerialHub, surface_ec, SurfacePlatformProfile).
Reality: the SLS2 driver stack has **8 drivers**, several with non-obvious names:

- `SurfaceIntegrationDriver.sys` is the modern integration root (89.0.7.0, dated 2026-05-06 — bleeding edge).
- `SurfaceSmfClient.sys` is the modern SAM client (8.163.8.0); the Linux equivalent is `surface_aggregator_cdev.ko`.
- `SurfaceAcpiPlatformExtensionDriver.sys` is **boot-start** (`StartType=0`, LoadOrderGroup `Core Platform Extensions`) and provides ACPI `_DSM` extensions. **This is the driver most likely to contain the missing dGPU power `_DSM` calls.**
- `SurfacePowerMeterDriver.sys` reads from both MAX34407/34417 hardware AND from the SAM device `{5AE6B5A3-26AE-4FCF-B774-6F7EB76FD072}` — power telemetry is partially SAM-driven.

### EC firmware is encrypted

EC.bin is PKCS#7 SignedData (first bytes `0xED 0xD5 ...` — DER-encoded
ContentInfo). Inside is the encrypted XLFF payload signed by "Microsoft Surface
Elmer Firmware Signer" against the "Microsoft Surface XLFF Firmware CA 2021"
chain. Static RE is not possible without per-device keys. We pivot to:
- .sys RE (PE32+ plaintext) — primary
- Live SAM frame capture (Phase 2) — primary
- ACPI table analysis — secondary
- UEFI/ME blob analysis (if any plaintext EC dump exists) — long shot

### Surface Overlay Power Settings

From `SurfaceIntegrationDriver.inf` — this is the **Windows analog of
`platform_profile`**:

- Subgroup GUID: `{bfeba2e4-fdcc-41d9-93f4-3f6991c1f730}`
- Setting GUID: `{a4a0ab02-11f1-4584-bc52-cbb98eabdb0b}`
- Overlay schemes:
  - Balanced (typical): `{381b4222-f694-41f0-9685-ff5bb260df2e}`
  - High Performance: `{3af9B8d9-7c97-431d-ad78-34a8bfea439f}`
  - Max Performance: `{ded574b5-45a0-4f42-8737-46345c09c238}`

On Linux, `surface_platform_profile.ko` maps these to 4 names:
`low-power`, `balanced`, `balanced-performance`, `performance`.
Confirmed via `cat /sys/firmware/acpi/platform_profile_choices`.

### Codename = Elmer

Microsoft's internal codename for the SLS2 EC firmware is **"Elmer"**,
visible in the signer CN `Microsoft Surface Elmer Firmware Signer`. The
EC FW build is 13.101.139 (matches the Linux surface_aggregator EC version
string for SLS2). Useful for cross-referencing Microsoft update-tracker
and LKML discussions.
